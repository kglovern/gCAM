# Controller output

Config → G-code output selects a controller preset and edits its command blocks.
grblHAL is the default. The existing geometry planners and motion emitters remain
in place; the output renderer changes commands and formatting at export time.
The same settings apply to combined exports, individual toolpaths and sender
handoff. Tool-change procedures remain in the host or firmware.

## Presets and limits

| Preset | Planar milling | Rotary | Laser |
| --- | --- | --- | --- |
| grblHAL | Existing default | A-axis firmware required; existing inverse-time paths retained | M4/S motion power; matching laser-capable output and power range required |
| Grbl 1.1 | Single-tool files; no firmware M6 | Blocked: stock Grbl has three axes | M4/S, laser mode required; settings are not changed |
| Duet / RRF 3.5+ | CNC mode and configured spindle slot required | Angular A axis and G93 support required | Configured laser mode; explicit S on cutting moves and S0 before travel |
| Marlin CNC / inline laser | Firmware spindle features required; linear output by default; millimetres | Blocked: no verified stock G93 output path | Inline M4 I / M5 I; matching build and power range required |
| LinuxCNC | Incremental IJK, G94 | G93, F on every cutting move | Blocked: HAL wiring and synchronized output channels are machine-specific |
| Mach3 Mill | Incremental IJK; dwell units must match General Config | G93 | Blocked: synchronized outputs depend on the motion plugin |
| Mach4 Mill | Incremental IJK, G94, CRLF and final newline | G93 | Blocked: synchronized outputs depend on the motion plugin |

These are documented starting profiles, not hardware certifications. Firmware
settings, pin assignments, homing and work offsets are not configured by export.
Laser and milling operations must be exported separately. Grbl and Marlin multi-tool
jobs can be downloaded as individual toolpaths; no tool-change sequence is invented.
Duet uses T selection. Other supported hosts receive the existing M6 request.

Marlin's preset assumes millimetre operation without inch-mode support. It omits
G20/G21 and G17 because their availability depends on firmware build options.
It does not emit M30: that command is not a portable program-ending command in
Marlin. Duet also uses end-of-file rather than a stop/sleep command.

Rotary remains in millimetres, with A in degrees. Existing XYZA paths retain their
planned inverse-time durations. Legacy XZA paths use their linear/angular travel
and programmed feed to produce inverse-time durations for the non-default
controllers. Angular distance uses the larger endpoint radius. G94 is restored
before the final retract. No rotary-axis remapping or Y-to-A substitution is added.

## Command blocks

Events are program start, operation start/end, spindle start/speed change/stop,
coolant on/off, laser start/stop and program end. Coolant defaults to empty.
Cutting geometry and safe retracts remain generated by CAM.

Blocks accept named substitutions, not executable JavaScript. All block distances
are authored in mm and feeds in mm/min. The renderer converts coordinate/feed
words to the application's output units; it never converts inverse-time F or
angular coordinates. Dwell format is independently selected. Rotary output is
always metric.

Job values: `jobName`, `spindleSlot`, `delaySeconds`, `delay`, `laserMax`,
`programEnd`. Operation values: `operationName`, `toolNumber`, `toolName`,
`toolDiameter`, `feedRate`, `plungeRate`, `safeZ`, `spindleSpeed`.

For example, `M3 S{spindleSpeed}` expands from CAM's planned RPM.
`delay` is converted to the selected dwell units; `delaySeconds` stays in seconds.
The configured spindle delay is emitted automatically after spindle start/speed
changes. Do not also add that delay to the block unless a second dwell is intended.

Unknown variables and sender expressions stop export. Blocks cannot change units,
plane, arc-centre mode or enter inverse-time/feed-per-revolution mode. Temporary
G91 moves must restore G90 in the same block. Custom commands still need to match
the machine: the renderer is not a full interpreter for controller macros.

## Defaults and saved settings

Selecting a controller loads its preset. Edits are saved locally as the current
custom configuration. Blank means emit nothing. Reset on
each block restores that controller's default. Export/Import Config includes the
entire effective profile. Reset All restores grblHAL.

Portable project files also contain the effective profile. Loading a project
restores its output settings and arc choice. Older projects use the grblHAL
default. Malformed imported profiles are rejected before the project is changed.

## CAM and sender boundary

CAM resolves job metadata, planned coordinates, RPM, feed and delays at export.
Live machine/work position, active firmware modes, probing results, operator
responses, pause/resume/abort events and session globals belong to the sender.
No runtime placeholders are passed through as though an ordinary file were a
gSender macro.

Evaluator reuse has not been claimed. Before reusing gSender code, inspect its
licence, parser/evaluator split, supported syntax, state dependencies, browser
compatibility, error behaviour, side effects and whether ordinary streamed files
actually enter the same evaluation path as macros/program events.

## Research references

Reviewed 28 October 2026. Kevin's Dev Log suggestion remains a proposal; this
implementation does not treat it as evidence of prior architecture approval.

- [MillMage custom G-code](https://docs.millmagesoftware.com/latest/Reference/DeviceSettings/CustomGCode/): editable commands coexist with dialect, dwell and tool options; temporary positioning changes require restoration.
- [Grbl supported commands](https://github.com/gnea/grbl#supported-g-codes) and [laser mode](https://github.com/gnea/grbl/blob/master/doc/markdown/laser_mode.md): M4 dynamic power and motion-associated S values.
- [grblHAL commands](https://github.com/grblHAL/core#supported-g-codes) and [laser plugins](https://github.com/grblHAL/Plugins_laser): build/driver-dependent axes and laser capability.
- [Duet G-code dictionary](https://docs.duet3d.com/User_manual/Reference/Gcodes/M586): G93/G94 from RRF 3.5, angular-axis configuration, laser mode, explicit motion power, dwell formats and spindle-slot addressing.
- [Marlin spindle/laser control](https://marlinfw.org/docs/features/laser_spindle.html), [M4](https://marlinfw.org/docs/gcode/M004.html), [axis configuration](https://marlinfw.org/docs/setting/stepper_drivers.html), [units](https://marlinfw.org/docs/settings/units.html), [M30](https://marlinfw.org/docs/gcode/M030.html): build/version dependencies and differing command meanings.
- [LinuxCNC G-code](https://linuxcnc.org/docs/html/gcode/g-code.html) and [M-codes](https://linuxcnc.org/docs/html/gcode/m-code.html): G93 requires F on every cutting block; M62/M63 and M67 are synchronized outputs requiring HAL connections.
- [Mach3 configuration](https://www.machsupport.com/wp-content/uploads/2013/02/Mach3Mill_Install_Config.pdf) and [programming](https://www.machsupport.com/wp-content/uploads/2013/02/Mach3Mill_1.84.pdf): selectable dwell units and inverse-time feed.
- [Mach4 Mill programming](https://www.machsupport.com/wp-content/uploads/2014/05/Mach4%20Mill%20GCode%20Manual.pdf): inverse-time feed, arc modes, dwell seconds and end-of-block requirements.
- [gSender macros](https://resources.sienci.com/view/gs-macros/): session globals, position inputs and program events.

## Regression coverage

Tests cover all seven milling presets; two-tool ordering and individual-export
fallback; second/millisecond dwell; inch coordinates and feeds; unchanged inverse
time and angular words; scaled laser power and restoration after travel; explicit
laser shutdown; unsupported combinations; invalid blocks/settings; and project
profile round trips. Existing CAM and rotary tests continue to cover motion.
